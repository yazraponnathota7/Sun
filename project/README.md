# SMART-Q Management — Smart Canteen Management System

A full-stack college project with **React + Vite**, **Java 21 + Spring Boot**, and **Supabase Auth + PostgreSQL + Storage + Realtime**.

## SMART-Q branding
This project is branded as **SMART-Q Management** for the Design Thinking / EST prototype demonstration. The existing CampusBite project folder name may remain in your extracted files; the student/admin interface and browser title use SMART-Q Management.

## Architecture and security
- React uses Supabase Auth for signup/login/session handling.
- The Spring Boot API validates Supabase JWTs (JWKS public keys, or the legacy HS256 secret if configured) and performs order/menu/admin operations against Supabase PostgreSQL.
- The backend obtains the caller's role from `profiles`; the UI's route guards are convenience only, not security.
- Order totals, stock/availability checks, token generation, order items and status history are handled server-side.
- Supabase RLS is enabled in `supabase/schema.sql` for direct client reads/profile access. Sensitive writes go through the Spring API.
- Payment: **Pay at Counter** always, plus optional **Pay online** through Razorpay (enabled only when `RAZORPAY_KEY_ID` and `RAZORPAY_KEY_SECRET` are set on the backend).
- Realtime is enabled for order/menu/notification tables; the app also refreshes data periodically as a fallback.
- Push notifications are not configured; in-app notifications are implemented.

## Prerequisites
- Java 21+
- Node.js 20+
- A Supabase project
- Maven 3.9+ (or use the Maven wrapper generated by your IDE)

## 1. Configure Supabase
1. Create a project at https://supabase.com.
2. Open **SQL Editor** and run `supabase/schema.sql` completely.
3. In **Authentication → URL Configuration**, set the local site URL to `http://localhost:5173`.
4. In **Storage**, the SQL creates a public `menu-images` bucket with upload restricted to admin users. Images are intended to be public; only authorized admins can upload/update/delete them.
5. Copy the Project URL and anon key from **Project Settings → API**.

### Create the first admin safely
Sign up the intended manager through the app's **Admin login → Create/authorize admin account** instructions in `supabase/ADMIN_SETUP.md`. Do not add a public admin signup. Run the documented SQL as the project owner in the Supabase SQL Editor after the account exists. For a friend acting as admin, authorize that friend's exact Auth UUID/email using the same trusted SQL-editor procedure.

## 2. Configure backend
Copy `backend/.env.example` to `backend/.env` (never commit it) or set the same variables in your host's dashboard:
- `SUPABASE_DB_URL`, `SUPABASE_DB_USERNAME`, `SUPABASE_DB_PASSWORD`: in Supabase click **Connect** and copy the **Session pooler** details (host `aws-0-REGION.pooler.supabase.com`, port `5432`, username `postgres.YOUR_PROJECT_REF`). The direct `db.<ref>.supabase.co` host is IPv6-only and fails on Render/Railway.
- `SUPABASE_URL`: `https://YOUR_PROJECT_REF.supabase.co`
- `SUPABASE_JWT_SECRET`: leave empty for new projects (tokens are verified through the public JWKS). Only fill it for older projects that still use the legacy HS256 secret (Project Settings, JWT).
- `APP_CORS_ORIGINS`: comma-separated frontend URLs, for example `http://localhost:5173,https://your-app.vercel.app`
- `APP_TIMEZONE`: used for "today" in the dashboard and reports (default `Asia/Kolkata`)

Start backend:
```bash
cd backend
mvn spring-boot:run
```
Health endpoint: `http://localhost:8080/api/health`

## 3. Configure frontend
Copy `frontend/.env.example` to `frontend/.env` and set `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY` and `VITE_API_URL` (backend URL ending in `/api`). Then:
```bash
cd frontend
npm install
npm test
npm run build
npm run dev
```
Open `http://localhost:5173`.

## 4. Deploy (works from a phone browser)
1. **Backend (Render, Railway or Fly):** Render has no native Java runtime, so deploy with Docker. Create a Web Service from your GitHub repo, set Root Directory to `backend`, runtime **Docker** (uses `backend/Dockerfile`), add the environment variables above, health check path `/api/health`.
2. **Frontend (Vercel or Netlify):** import the repo, Root Directory `frontend`, framework Vite. Add `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY`, `VITE_API_URL=https://YOUR-BACKEND.onrender.com/api`. `vercel.json` and `public/_redirects` already handle page refreshes on routes like `/orders`.
3. Add the Vercel URL to the backend's `APP_CORS_ORIGINS` and redeploy the backend.
4. In Supabase, **Authentication, URL Configuration**: set Site URL and a Redirect URL to the Vercel URL.
5. Create the admin account (`supabase/ADMIN_SETUP.md`).
Free Render services sleep when idle, so the first request after a break can take about a minute.

## Online payments (Razorpay, optional)
1. Create a Razorpay account and copy the **Test** keys (Dashboard, Account & Settings, API Keys). Use `rzp_test_...` keys until everything works.
2. In Razorpay, set **Payment Capture** to **Automatic** (Settings, Payment Capture).
3. Add `RAZORPAY_KEY_ID`, `RAZORPAY_KEY_SECRET`, and `RAZORPAY_WEBHOOK_SECRET` to the backend environment (never to the frontend) and redeploy. The "Pay online" option then appears at checkout.
4. Re-run `supabase/schema.sql` once (it is idempotent) to add the payment columns.
How it works: the server creates the Razorpay order and verifies the payment signature itself. Unpaid online orders stay hidden from the kitchen until paid. Cancelling a paid online order refunds it automatically. A student whose payment window closed can finish from the order page ("Pay now"). For production, also add a Razorpay webhook as a safety net.

## Password reset
In Supabase, Authentication, URL Configuration: add `https://YOUR-FRONTEND/reset-password` (and `http://localhost:5173/reset-password`) to **Redirect URLs**. Configure SMTP under Authentication, Emails for reliable delivery in production. Students use **Forgot password?** on the sign-in page.

## Notifications
Students see a bell in the top bar with an unread count (refreshed every 15 seconds). Order accepted, preparing, ready, completed, cancelled and payment received events appear there.

## Main workflows
- Student signup/login, live menu, search/category filters, cart, checkout, server-priced order creation, unique pickup token, live order tracking, order history, notifications and profile.
- Separate admin login entry. Only profiles with database role `admin` can use admin API routes.
- Admin dashboard statistics, queue/order status workflow, menu create/edit/availability, reports and image upload.
- All dashboard metrics and order lists are database-backed.

## API outline
- `GET /api/menu`, `GET /api/categories`
- `POST /api/orders`, `GET /api/orders/mine`, `GET /api/orders/{id}`
- `GET /api/notifications`, `PATCH /api/notifications/{id}/read`
- Admin: `GET /api/admin/dashboard`, `GET /api/admin/orders`, `PATCH /api/admin/orders/{id}/status`
- Admin menu: `POST /api/admin/menu`, `PUT /api/admin/menu/{id}`, `DELETE /api/admin/menu/{id}`
- Reports: `GET /api/admin/reports?from=YYYY-MM-DD&to=YYYY-MM-DD`

## Notes
- Run `supabase/schema.sql` before starting the application.
- This project uses a server-side PostgreSQL connection. Do not expose database credentials or Supabase service-role keys in React.
- The JDBC backend uses a trusted DB connection and performs authorization in Spring services. RLS still protects browser-side access. Do not add direct browser write policies for orders or order status.
- The included app is a strong runnable project foundation, but validate it against your own Supabase project's current Auth/JWT settings before production deployment. Add rate limiting, audit logging, monitoring, backups and a payment provider before real-world use.
